# Phase 5 - 데이터 품질, Curated 계층, 재처리 전략

## 이번 Phase의 목적

Phase 5의 목적은 주식 데이터를 더 많이 모으는 것이 아니라, 이미 모은 데이터가 모델 학습과 대시보드 조회에 사용할 수 있는 상태인지 반복해서 확인하는 구조를 만드는 것이었다.

일봉 수집이 매일 성공하더라도 그것만으로 데이터 플랫폼이 안정됐다고 볼 수 없다. 같은 날짜가 중복될 수 있고, 거래소 휴장일을 누락으로 착각할 수 있으며, 공급자가 특정 날짜의 가격을 잘못 줄 수도 있다. 따라서 Phase 5에서는 다음 질문에 답하는 것을 목표로 했다.

- raw 데이터와 processed feature의 날짜가 일치하는가?
- 중복 날짜가 생기지 않는가?
- OHLC 관계가 논리적으로 맞는가?
- 거래소가 열린 날인데 데이터가 빠진 것은 아닌가?
- 공급자 이상을 raw에서 지우지 않고 별도 기준 데이터로 정리할 수 있는가?
- 같은 재처리를 여러 번 실행해도 결과가 깨지지 않는가?
- Airflow에서 품질 오류를 발견하면 Task를 실패시킬 수 있는가?

## 첫 품질 검사에서 발견한 문제

29개 종목의 raw와 processed 데이터를 검사했을 때 단순 결측이나 중복은 없었지만, 실제 데이터 제공자의 특성이 드러났다.

| 문제 | 결과 | 처리 방향 |
| --- | ---: | --- |
| SK하이닉스 보정주가 0 이하 | 778행 | raw 보존, curated에서 `NaN` 처리 |
| 한국장 OHLC 관계 모순 | 16행 | 보조 공급자와 비교 후 curated에서 교체 |
| 긴 날짜 공백 | 여러 구간 | 거래소 캘린더로 실제 휴장과 누락 구분 |
| 전일 거래량 0으로 인한 무한대 피처 | 다수 | feature 계산에서 무한대를 결측 처리 |

여기서 중요한 점은 원천 파일을 바로 수정하지 않았다는 것이다. 공급자가 준 값은 `raw/provider=yfinance`에 그대로 남기고, 검증과 보정 결과는 `curated` 계층에 따로 만들었다.

## 거래소 캘린더를 사용한 이유

처음에는 날짜 차이가 7일을 넘으면 누락으로 볼 수 있다고 생각했다. 하지만 한국장은 추석이나 임시공휴일이 길게 이어질 수 있고, 미국장도 오래된 데이터에서는 캘린더 정의가 완벽하지 않을 수 있다.

예를 들어 `2017-09-29 -> 2017-10-10`, `2025-10-02 -> 2025-10-10` 구간은 단순 날짜 차이만 보면 누락처럼 보였지만, XKRX 거래 캘린더로 확인하면 실제 장기 휴장 구간이었다.

그래서 품질 검사는 달력 일수가 아니라 예정 거래 세션을 기준으로 바꿨다.

```text
시장별 거래소 캘린더
  -> 예정 거래일 생성
  -> 실제 raw/curated 날짜 집합과 비교
  -> 실제 휴장은 정상
  -> 예정 거래일인데 데이터가 없으면 경고
```

캘린더도 완전한 정답은 아니었다. XKRX에 반영되지 않은 `2007-03-02` 임시공휴일과 2026년 일부 휴장일은 프로젝트 예외 목록으로 관리했고, XNYS의 오래된 휴일 오탐은 미국장 세션 누락 검사를 1970년 이후로 제한해 처리했다.

## 보조 공급자와 Curated 계층

한국장에서는 `pykrx_naver`를 보조 공급자로 연결했다. 이 이름을 명확히 붙인 이유는 중요하다. pykrx의 `adjusted=False` KRX 원시 시세 경로는 인증 정보가 필요했고, 인증 없이 사용할 수 있는 경로는 Naver 기반 수정주가였다. 따라서 이를 KRX 원천이라고 부르지 않고 `pykrx_naver`로 분리했다.

Yahoo에서 OHLC 관계가 깨진 16개 날짜는 pykrx_naver에서 정상적인 행을 확인했다. 예를 들어 삼성전자 `2024-10-14`는 Yahoo의 종가가 저가보다 낮아 일봉 관계를 위반했지만, pykrx_naver 값은 정상 범위였다.

최종 저장 흐름은 다음과 같다.

```text
raw/provider=yfinance
raw/provider=pykrx_naver
          |
          v
공급자 비교와 품질 판정
          |
          v
curated/market_data
          |
          v
processed/features
```

이 구조 덕분에 원천 데이터는 보존하면서도 모델 학습이나 화면 조회에는 더 일관된 기준 데이터를 사용할 수 있다.

## 재처리와 멱등성

Phase 5에서는 백필과 재처리를 구분했다.

백필은 공급자에서 과거 또는 최근 구간을 다시 받아 raw에 병합하는 작업이다. 날짜 기준으로 merge/dedup을 수행하므로 같은 구간을 다시 받아도 중복이 늘어나지 않는다.

재처리는 이미 저장된 raw 또는 curated를 읽어서 processed feature를 다시 만드는 작업이다. 이 명령은 기본이 dry-run이고, 실제 저장은 `--write`를 명시해야 한다.

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python \
  -m chartmaster.pipelines.local_market_data_reprocess \
  --market KR \
  --tier all
```

이렇게 둔 이유는 실수로 과거 feature를 덮어쓰는 것을 막기 위해서다. 데이터 엔지니어링에서는 재실행 가능성만큼이나 잘못된 재실행을 막는 장치도 중요하다.

## Airflow 품질 Gate

한국장 DAG는 다음 구조로 확장했다.

```text
collect_kr_daily_ohlcv
  -> curate_kr_market_data
  -> validate_kr_market_data
```

미국장 DAG는 아직 보조 공급자 교정이 필요하지 않아 다음 구조를 유지한다.

```text
collect_us_daily_ohlcv
  -> validate_us_market_data
```

품질 검사에서 error가 하나라도 나오면 Task는 실패한다. 반면 공급자 한계처럼 바로 오류로 단정하기 어려운 항목은 warning으로 남기고 DAG는 성공시킨다.

이 구분이 중요하다. 모든 경고를 실패로 만들면 매일 운영이 불안정해지고, 모든 문제를 성공으로 넘기면 데이터 문제가 조용히 누적된다. Phase 5에서는 모델 학습을 막아야 하는 구조 문제와 사람이 확인해야 하는 공급자 한계를 분리했다.

## 이번 Phase에서 배운 점

첫 번째는 raw를 수정하지 않는 습관이다. 원천 데이터에 문제가 있어도 바로 덮어쓰면 나중에 어떤 값이 공급자 응답이고 어떤 값이 프로젝트 판단인지 추적할 수 없다.

두 번째는 거래일 검증은 단순 날짜 차이가 아니라 거래소 캘린더 기준이어야 한다는 점이다. 특히 한국장은 장기 휴장과 임시 휴장이 많기 때문에 달력 기준 검사는 오탐이 많았다.

세 번째는 품질 오류와 경고를 분리해야 한다는 점이다. 오류는 파이프라인을 멈춰야 하는 문제이고, 경고는 운영자가 확인해야 하는 문제다. 이 기준을 세워야 Airflow 품질 Gate가 실무적인 의미를 가진다.

네 번째는 재처리 명령은 멱등성과 안전장치를 가져야 한다는 점이다. 같은 명령을 반복해도 중복이 늘어나지 않아야 하고, 실제 저장은 명시적으로 요청했을 때만 일어나야 한다.

## Phase 5 완료 기준

Phase 5는 다음 기준을 만족했기 때문에 완료로 처리한다.

- 데이터 품질 검사 스크립트를 구현했다.
- 거래소 캘린더 기반 누락 검사를 구현했다.
- 한국장 보조 공급자 교차 검증과 curated 계층을 만들었다.
- raw, curated, processed 계층을 분리했다.
- 재처리 명령과 runbook을 만들었다.
- PostgreSQL에 품질 이슈 기록 구조를 추가했다.
- Airflow DAG에 품질 Gate를 연결했다.
- 실제 서버2 데이터 기준으로 29개 종목 품질 검사를 통과했다.
- 한국장과 미국장 Airflow 실행 성공을 확인했다.

KRX 인증 기반 원시 시세 검증은 아직 남아 있지만, 이는 현재 Phase의 핵심 구조를 막는 문제라기보다 공급자 신뢰도를 더 높이는 후속 보강 항목이다. 네트워크 단절, DB 중단, 강제 실패 같은 장애 주입 테스트와 백업/복구 훈련은 Phase 6 운영 안정성에서 다룬다.

## 포트폴리오 설명 문장

주식 시장 데이터의 raw, curated, processed 계층을 분리하고, 거래소 캘린더 기반 품질 검사를 Airflow DAG에 연결했습니다. yfinance 원천 이상을 raw에서 보존한 채 pykrx_naver 보조 공급자로 교차 검증해 curated 데이터를 생성했고, 재처리와 중복 방지, 품질 리포트 저장, 오류 기반 Task 실패 조건을 구현했습니다. 최신 서버2 데이터 기준 29개 종목 전체 품질 검사를 통과했으며, 한국장과 미국장 정기 Airflow 실행 성공을 확인했습니다.
